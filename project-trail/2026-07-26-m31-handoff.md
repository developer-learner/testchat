## The three defects (all TPM-authored, all in the spec)

### 1. `src/static/current-chat.css` can never be loaded — the deep one

The spec adds a new stylesheet to the inventory. Nothing can ever link it:

```
src/static/index.html:7   <link rel="stylesheet" href="/static/style.css">   ← the only link
```

* `index.html` is outside the delta scope, so the coder may not edit it
  (orchestrate printed `delta v63 touches: T7 — every other existing file is
  no-edit`).
* `style.css` is in frozen `contracts.no_edit_files`.

So the file would be written and then be dead code, and the highlight ACs
would fail with no visible cause. Catching this needed one command —
`grep link index.html` — run at spec time. It was not run.

**Why `index.html` cannot simply be pulled into scope:** `cmd_affected`
(`scripts/validate-plan.py:770`) computes the editable set from
`tests ∩ changed_tests`, `contracts ∩ changed_contract_ids`, and
`file ∈ changed_files`. `refreeze.sh` hardcodes `changed_files: []`, and its
contract-delta walks only `entry_points`/`routes`/`schemas`/`errors` — **never
`ui` entries**. The one remaining lever is the EM's test mapping, and the EM
assigned 49 tests to `app.js` versus 2 to `index.html`; it treats `app.js` as
the owner of UI behaviour. Fighting that is unreliable.

### 2. The smoke_check is quote-brittle — caused the halt

```
grep -q '\[data-active="true"\]' src/static/current-chat.css
```

The coder wrote `[data-active='true']` (single quotes). Identical CSS. The
non-color-signal half of the check passed. This burned 4 coder strikes and 2 EM
diagnoses against a **correct** file. A shell grep for a source token must be
quoting-agnostic:

```
grep -qE "\[data-active=['\"]true['\"]\]" <file>
```

### 3. The dependency chain amplifies any failure

```
T7 (src/static/app.js) depends_on = [T1..T6, T8..T13]   → status: blocked
```

`T7` is the entire implementation and depends on all twelve other tasks,
including the CSS task. One CSS smoke_check failure blocked every line of real
work. Dropping the CSS file removes this edge as a side effect.

## Recommended v64 repair

**Drop `src/static/current-chat.css`; `app.js` injects its own `<style>`
block.** This resolves all three defects at once: no unreachable stylesheet, no
blocking `T13`, no edit needed to `index.html` or the frozen `style.css`, and
everything lands in `app.js` — the one file reliably inside delta scope.

## Pipeline gotchas learned this session

1. **A spec-only refreeze silently destroys delta scoping.** `changed_tests` is
   populated from *presence of a test file in staging*, not from content
   differences (`refreeze.sh:527`). v62 changed only `contracts.json`, so
   `DELTA-v62.json` came out empty (`changed_tests: 0`), and the inverted
   no-edit default then locked the coder out of every existing file. The fix is
   to **restage `tests/test_ui.py` byte-identical** in any delta that must keep
   an unbuilt milestone in scope — that alone repopulated `DELTA-v63.json` to 45
   changed tests. Any v64 must do the same.

2. **Every task needs an acceptance signal at freeze time.** A file in
   `contracts.files` with no mapped test and no `smoke_checks` entry fails the
   plan gate for *every* EM — v61 burned two full EM calls (530s) proving it.
   `validate-plan.py` enforces this and can be run against a staged artifact
   before freezing.

3. **Re-verifying untouched files is nearly free** — measured at 1–2s per task,
   not the tens of seconds assumed. It is not worth optimising. The EM plan call
   (~282s) is ~91% of a clean run's wall clock, because the EM re-emits a full
   13-task plan (19.5k chars) when only three tasks changed. That is the only
   phase worth optimising, and a plausible blueprint D-number.

4. **Seeded `.pipeline-state/tasks/` markers do not survive a re-plan.**
   Fingerprints cover file/brief/tests/contracts; a regenerated plan produces
   new brief wording, so every task resets to pending regardless. Their real
   value is passing the fail-closed empty-state check, not skipping work.

5. **Worktrees work fine with the podman sandbox** (170 tests collected from a
   worktree) and with `phase-gate.sh`, despite `.git` being a file rather than a
   directory.

## Process note

Every one of the three defects was mechanically detectable before the freeze,
using tools already in this repo. The failure mode was authoring spec artifacts
and freezing them without executing the checks the pipeline would later apply —
verification discipline, not reasoning difficulty. Three refreeze cycles and
roughly 90 minutes were spent on defects that a pre-freeze pass would have
caught.

Two of them are gate-shaped and would protect any future TPM:

* **new-file reachability** — a file added to `contracts.files` that no entry
  point, template, or existing file references is dead on arrival;
* **non-empty delta** — a delta whose `changed_tests` is empty while the
  milestone is unbuilt silently disables the coder's write scope.

Consistent with the blueprint's own rule that an unenforceable rule is only a
suggestion.
